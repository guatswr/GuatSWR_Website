## 2. 真实查询计划（EXPLAIN QUERY PLAN）基准分析

对各主要业务查询在包含 500+ 条真实数据的数据库上进行 `EXPLAIN QUERY PLAN` 执行计划检验：

| 业务场景 | 实际 SQL 语句模式 | 索引命中情况 | 优化前计划 | 优化后计划 |
| --- | --- | --- | --- | --- |
| **公开活动列表（无类型）** | `SELECT ... FROM events WHERE status IN (...) ORDER BY created_at DESC LIMIT 20` | `idx_events_status_created` | `SCAN events` + `USE TEMP B-TREE FOR ORDER BY` | `SEARCH events USING INDEX idx_events_status_created (status=?)` |
| **公开活动列表（带类型）** | `SELECT ... FROM events WHERE status IN (...) AND type = ? ORDER BY created_at DESC LIMIT 20` | `idx_events_type_status_created` | `SCAN events` + `USE TEMP B-TREE FOR ORDER BY` | `SEARCH events USING INDEX idx_events_type_status_created (type=? AND status=?)` |
| **管理端单状态审核** | `SELECT ... FROM events WHERE status = 'pending' ORDER BY created_at DESC LIMIT 20` | `idx_events_status_created` | `SCAN events` + `USE TEMP B-TREE FOR ORDER BY` | `SEARCH events USING INDEX idx_events_status_created (status=?)`（**零临时 B-Tree 排序**） |
| **活动分页总数统计** | `SELECT COUNT(*) FROM events WHERE status IN (...)` | `idx_events_status_created` | `SCAN events` 全表扫描 | `SEARCH events USING COVERING INDEX idx_events_status_created`（**覆盖索引扫描，零数据页读取**） |
| **成员有效列表排序** | `SELECT * FROM members WHERE deleted_at IS NULL ORDER BY sort_order ASC, id ASC` | `idx_members_active_sort` | `SEARCH members USING INDEX idx_members_deleted_at` + `TEMP B-TREE FOR ORDER BY` | `SEARCH members USING INDEX idx_members_active_sort (deleted_at=?)`（**无文件排序**） |

> **通配符查询说明**：`audit_logs` 的后台模糊搜索采用 `%keyword%` 前导通配符语义。根据规范约束，保持既有搜索语义不变，不擅自改成前缀匹配；既有 `idx_logs_created_at` 与 `idx_logs_username` 保持正常生效。
