## 1. 变更范围与文件清单

1. `backend/src/security/bans.ts`：
   - **有界轻量 DTO 缓存（`BoundedBanCache`）**：
     - 维护容量上限为 2048 项的短生命周期（默认 TTL 5,000ms）内存缓存。
     - 仅存储精简 DTO：`{ blocked: boolean, reason: string, expiresAt: number | null, cachedAt: number, ttl: number }`，消除深层对象与 Promise 引用。
     - 容量满时采用 FIFO/最老淘汰机制，防止外部恶意请求突发大量不同 IP 导致内存溢出。
   - **到期寿命精准钳位（Clamped TTL）**：
     - 缓存条目的有效寿命取 `Math.min(defaultTtlMs, expiresAt - now)`。
     - 确保临时封禁记录在到期时立即放行，绝对不会因为短期缓存而发生封禁时间被非预期延长的情况。
   - **故障隔离与不缓存失败**：
     - 数据库查询失败时记录告警并执行既有安全策略（Fail-Open 返回 `undefined`），绝不将失败结果或错误 Promise 写入缓存，防止瞬时 DB 抖动污染缓存。
   - **主动失效机制**：
     - `ban(ip, ...)` 事务提交后，立即主动执行 `cache.delete(ip)`，新封禁无需等待 TTL 立即全站生效。
     - `unban(ip, ...)` 事务提交后，立即主动执行 `cache.delete(ip)`，解封操作立即生效。
     - 定时清理任务 `cleanup()` 触发时，同步清空缓存 `cache.clear()`。
2. `backend/tests/integration/ban-cache.test.mjs`：
   - 新增专项集成测试套件，全面覆盖 6 项核心机制：
     1. 重复查询命中缓存，大幅减少底层 SQLite 读取；
     2. 新增封禁与解封在提交后主动失效缓存，零等待生效；
     3. 临时封禁到期后立刻放行，TTL 精准约束不超期；
     4. 模拟数据库异常时安全 fail-open 且绝不污染缓存；
     5. 大量不同 IP 突发查询下严格维持 50 槽位容量上限；
     6. `cleanup()` 清除过期数据的同时清空缓存。
