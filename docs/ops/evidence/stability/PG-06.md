## 实际执行

入口：`pnpm test:release`；完整 PG 回归：`pnpm test:postgres`。

隔离 harness 固定 PostgreSQL 18.6 镜像 digest、loopback 动态端口、合成账号和唯一数据库。测试自己创建并清理容器、匿名卷、恢复副本和候选数据库，不连接生产。

1. 用真实 SQLite 迁移生成 main 10 / audit 2，全 30 表非空；生成并验证 full backup，恢复为冻结源。
2. 导入全新 PG，检查逐表摘要、外键、序列和本地文件。实际启动最小权限 backend，访问 readiness/config，登录并提交受保护新文章。
3. 在另一个新目标的导入事务 commit 前真实抛出故障，检查表为空。由同一未修改冻结源导入另一个 PG 候选并实际启动；复查原冻结源文件摘要未变。
4. 对包含新 PG 写入的库执行原生备份，恢复到第三个空数据库和新资源目录。启动候选、登录、读出新文章和图片并核对字节，再新增文章证明序列安全。

不存在 provisioner 或验证源时立即报错，不允许离线返回 ALL_REHEARSALS_VERIFIED。最新本地报告由测试生成在 `.tools/release-rehearsal-report.json`，CI 将其作为 artifact 上传；本轮验证汇总见 [PRODUCTION-REVIEW-FIXES.md](PRODUCTION-REVIEW-FIXES.md)。报告耗时仅表示当前小型合成数据，不代表生产维护窗口。
