## 本轮交付

- `backend/src/database/contracts.ts` 提取 SqlValue、SqlExecutor、DatabaseStore、错误分类和跨驱动事务作用域；sqlite.ts 保留原类型及类的兼容导出。原有 SQL、数据库文件、迁移校验和均保留。
- `postgres.ts` 使用原生 pg 异步连接池，默认 4 个连接，最多 128 个等待者，获取超时 1000ms；同一事务独占 client，排队查询有序执行。回调即使捕获数据库错误也整体回滚；嵌套/外部存储/逃逸 executor 拒绝访问。
- 每次取消只销毁自己的 leased client。Linux PostgreSQL 18 会话设置 `client_connection_check_interval=100ms`，实测取消一个已在服务器执行的 10 秒查询后，另一连接能在 1500ms 断言范围内写入相同唯一键，证明服务端锁也已释放。该候选不承诺原生 Windows PostgreSQL 的同等取消语义。
- `close()` 停止新请求，拒绝排队者，默认宽限 1000ms 后取消残余；迟到连接由原槽位持有至销毁，避免超时泄漏。已确认提交不会仅因随后停机而被报告失败。
- SQLSTATE 23505/23503→constraint，40001→serialization，40P01→deadlock，55P03/53300→busy，57014→interrupted；连接失败及服务重启→unavailable。提供安全 HTTP 投影，冲突 409、依赖不可用 503，其余服务器错误 500；PG-02 路由切换时接入该投影，现有 SQLite API 错误行为保留。
- 不自动重放任何回调。COMMIT 已发送但响应丢失时返回 `outcome_unknown`，不标记可重试；测试注入“实际已提交、客户端丢响应”，验证记录只写一次且结果为待确认。
- 驱动局部解析 BIGINT 为安全 number；越界拒绝，不修改 pg 全局 parser。BYTEA 保持 Buffer，timestamp/date/numeric 保持 text，避免时区/小数精度变化。
- `config.ts` / `factory.ts` 提供配置及适配器工厂。默认 SQLite；PostgreSQL URL 仅来自私有 `POSTGRES_URL`，错误不包含连接字符串。应用初始化检测到显式 postgres 时返回 `DATABASE_DRIVER_NOT_READY`，在打开 SQLite 或创建目录之前退出。

## SQL 兼容边界

PostgreSQL 查询使用原生 `$1` 等参数，不翻译 SQLite 的问号、方言或冲突策略。扩展查询协议拒绝多语句；字符串、注释、JSON `?` 操作符原样保留。

`run()` 的 `changes` 来自 rowCount；新插入的数值 ID 必须由调用者显式 `RETURNING id` 才返回 lastID。无返回 ID 时 lastID 为 0；TEXT 主键仍通过 get/all 的行读取。PG-02 必须逐个适配依赖 lastID 的业务插入，不能直接把现有仓储接到工厂后上线。

SQLite sqlite3.run 对 RETURNING 的 changes 行为不同，共用契约的 SQLite 插入使用原有 lastID，PG 插入显式 RETURNING；两者测试的是同一业务元数据契约。

原有 PRAGMA、sqlite_master、strftime、INSERT OR REPLACE/IGNORE、回调 db/logDb、BFF 同步 Map、审计 outbox、资产清理和文件发布边界仍按 [PG-00 清单](PG-00-inventory.md) 进入 PG-02～05，不由适配器伪装兼容。

## 固定依赖与隔离环境

- pg / @types/pg：8.23.1，锁文件精确锁定；查询 npm 官方 registry 核对发布早于仓库 1440 分钟最小发布年龄。pg 支持 Node 24，安装过程未放宽发布年龄、构建权限或 peer 约束。
- PostgreSQL：18.6-bookworm，固定 digest `sha256:f1ea2a1a4fb7b68d4836be1fdcb8a6466a89b072158bf9d97663600538c294c5`。
- 测试入口：Node 24.16.0 环境执行 `pnpm test:database`。脚本创建带专属标签的唯一容器、127.0.0.1 临时固定端口和匿名数据卷；结束时验证标签后删除该容器及其匿名卷。
- 数据库为 `guatswr_pg_contract_test`，合成迁移角色与无 DDL 运行角色。全部测试拒绝非 127.0.0.1 或不匹配的库名；未读取生产配置、生产数据或 Umami。
- PostgreSQL fixture DDL 仅用于适配器契约，不是网站生产 schema，不可拿来导入真实业务表。
