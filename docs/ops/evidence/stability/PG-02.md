## 本轮结果

后端现在可在显式 `DATABASE_DRIVER=postgres` 时使用原生 PostgreSQL main/audit 存储。默认仍为 SQLite；未修改真实环境配置、旧数据库或 Umami。BFF 会话与访客草稿的异步 PostgreSQL 存储属于下一阶段 PG-03。

- `backend/src/migrations/postgres/001-baseline.sql`：30 张网站来源表，独立 main/audit 模式、原有外键、唯一约束、部分索引、成员 revision 触发器和必要日期函数。原有 SQLite SQL 文件及校验和保持不变。
- `manifest.json` / `engine.ts`：显式空库初始化、校验和、独立 schema_version、幂等重查与结构指纹。指纹覆盖列、默认值、索引、约束、函数、触发器及序列配置；不包含随业务变化的序列当前值。
- `database/application.ts`：启动只读校验既有模式与运行角色，通过后才创建文件目录。PG 分支不打开 SQLite，不自动 DDL，不回退或初始化空 SQLite。
- 运行连接总预算 main=3/audit=1；等待预算 main=96/audit=32，总计 4 个连接/128 个等待者。获取及锁等待默认 1000ms，停机有界排空并取消残余。
- 网站迁移角色和运行角色分开；初始化拒绝超级用户、迁移者成员等运行角色，授予 CONNECT/模式 USAGE/DML/序列 USAGE，撤销 PUBLIC 的 CREATE/TEMP。启动还会拒绝具有高权限或相关 CREATE/TEMP 权限的账号。运行账号不能修改 schema_version。
- 审计 addLog 改为异步存储并纳入关闭过程；安全审计继续使用原有 main outbox → audit 去重 → main 确认协议，保留提交与确认之间的崩溃恢复语义。

## SQL 与 DTO 兼容

业务查询源码已改为显式 `$n` 参数、`RETURNING id` 和逐表 `ON CONFLICT` 策略；PostgreSQL 适配器没有 SQLite SQL 翻译层。SQLite 继续支持原有问号参数，同时按名称绑定 `$n`，确保乱序和重复编号有一致语义。SQLite 对带 RETURNING 的 run 元数据在同一连接上确认 changes/lastID。

`site_config` 冲突更新只覆盖 value；`banned_ips` 冲突更新覆盖原 REPLACE 的全部业务字段；IGNORE 的各业务场景分别明确冲突目标。没有把 REPLACE 改成忽略更新。

- NULL 比较使用 `IS [NOT] DISTINCT FROM`；可空日期、排序值和学校字段显式声明 NULL 排序。
- TEXT 使用 COLLATE "C"；日志 LIKE 保持 SQLite 的 ASCII 大小写匹配和反斜杠语义。私有日志的负 LIMIT/OFFSET 兼容旧结果。
- UTC 文本时间使用 statement_timestamp 的显式 UTC 格式，公开日志继续输出北京时间 `+08:00`；毫秒整数在 CASE 中显式 BIGINT，避免 PostgreSQL 推断成 32 位整数。
- 历史 JSON 保留 TEXT，不转换或吞掉非法历史值；日期查询验证真实日历日期，损坏闰日不会抛错或被移动到其他日期。
- 数值 ID 保持安全 number。identity 序列上限及主键 CHECK 阻止超出 JavaScript 安全整数的行提交；非法数值 URL ID 保持未命中结果。
- 依赖不可用/锁等待使用安全 503、冲突使用 409；通用服务器故障保留各既有路由的错误 envelope、诊断和历史状态约定。SQL、连接串、原生错误详情不会进入响应。

SQLite 允许的 NULL TEXT 主键在 PostgreSQL 中不可导入；这种历史数据必须由 PG-04 诊断并停止导入，不会自动删除或改造。实际数据、ID/序列导入校准尚未执行。

## 并发保护

| 范围 | PostgreSQL 保护与验证 |
| --- | --- |
| 投稿/报名/取消/结算 | 同一事件行锁；提交回执与通知同事务；并发合并保留所有字段 |
| 文章修订/恢复 | 文章行锁，版本与正文原子提交 |
| 管理员权限/撤销/bootstrap | 安全域事务锁，保护最后超级管理员及在途权限重检 |
| Bot 凭据/通知/租约 | 凭据行锁、按去重 key 的事务锁、delivery 行锁与 SKIP LOCKED |
| 成员同步 | 群及任务行锁，保护 generation、批次与重复应用 |
| 文件发布/清理 | 共享资产域事务锁，使文件身份复查/业务提交与清理重命名互斥；保留影子索引未命中时的权威扫描 |

这些锁按业务域或具体记录协调，不使用全站数据库写事务锁替代 PostgreSQL 并发。回调不自动重放；COMMIT 结果未知仍按 PG-01 的待确认规则处理。
