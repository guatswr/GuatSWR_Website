## 1. 变更范围与文件清单

1. `backend/src/database/sqlite.ts`：
   - **连接 Lease 复用体系**：
     - 保留 `SqliteStore` 既有外部契约（`get`, `all`, `run`, `transaction`, `close`）与 `AsyncLocalStorage`（`transactionScope`）边界。
     - **独占写 Lease（Writer Lease）**：维护单一写入连接 `writerDb`，由 `withWriter` 进行严格排队调度与独占借调。连续写入与事务直接复用已配置好的连接，不再为每个 SQL 语句或事务无端创建和关闭原生 SQLite 连接。
     - **有界读 Lease 池（Reader Lease Pool）**：维护最大容量为 `maxReaders`（默认 4，上限 16）的只读连接池。读操作通过 `acquireReader` 借出、`releaseReader` 归还，等待队列上限 128 项并受 `busyTimeoutMs` 超时管控。
   - **精准写入与 CTE 判定（`isWriteStatement`）**：
     - 严格区分只读与写入语句。不仅识别前导 `INSERT|UPDATE|DELETE|REPLACE`，更对 `WITH` 公用表表达式（CTE）执行内部变动探测：凡包含 `INSERT|UPDATE|DELETE|REPLACE` 的 CTE 统一判定为写操作，强制调度至独占写 Lease，杜绝将写入 CTE 误分配给读连接。
   - **隔离中断与自愈重建**：
     - 取消操作（AbortSignal）仅触发对应借出连接的 `db.interrupt()`，绝不影响其他并发连接。
     - 严格保证“取消完成前不能归还”：底层异步查询回调完成并处理完潜在回滚后，方可在 `finally` 阶段触发归还或销毁。
     - 遇致命错误（`unavailable`）或中断时，连接标记为损坏并安全销毁（`destroyWriterDb` / `closeConnection`），并在后续需要时有限重建。
   - **优雅退出两阶段排空（`close`）**：
     - 调用 `close()` 时立即可靠置位 `isClosing`，拒绝所有后续新请求（抛出 `DatabaseError('scope')`）。
     - 触发内部 `shutdown.abort()`，立即唤醒并排空队列中的写等待者与读等待者（抛出 `DatabaseError('interrupted')`），无悬挂等待者。
     - 等待所有已借出在途操作（`active`）自然退出后，批量关闭写连接与全部池化读连接。
2. `backend/tests/integration/transactions.test.mjs`：
   - 保持全部 19 项底层事务、约束、并发与中断测试用例 100% 通过。
   - 新增针对连接池有界复用的专项断言用例：连续执行 100 次读写操作及 20 路并发读取，连接复用良好，连接创建数不再随 SQL 操作量线性增长。

## 2. 核心架构改进与对比

| 指标 / 行为 | 改造前 (旧实现) | 改造后 (DB-01) |
| --- | --- | --- |
| **连接创建开销** | 每个 SQL 或事务均执行 `new sqlite.Database()`，高并发下数千次创建/关闭 | 写操作复用 1 个连接，读操作在至多 4 个连接间复用，连接创建数 O(1) |
| **CTE 语句分类** | 仅按前缀判断，可能将修改型 CTE 漏判为只读 | `isWriteStatement` 深度匹配，含变动的 CTE 强制走写 Lease |
| **连接中断安全性** | 中断与关闭直接销毁，无连接健康状态追踪 | 仅中断自身持有的独占连接；异常连接安全隔离销毁并按需有限重建 |
| **停机退出行为** | 仅中止在途事务，队列等待者可能发生竞态 | 立即拒绝新进请求，主动唤醒排空所有队列等待者，无悬挂句柄 |
