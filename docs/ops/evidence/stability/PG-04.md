# PG-04 离线迁移修复证据

日期：2026-11-08。状态：CODE_VERIFIED（本地隔离验证；生产未验收）。旧版模拟 pg 校验和硬编码成功结果不能证明可导入，相关结论撤回。

## 实现

- `prepare-source.mjs` 要求已知完整备份 SHA-256，调用现有 backup_bundle.py 实际 verify 和 restore，生成数据库文件摘要标记。迁移 CLI 只接受该冻结恢复副本，检查 SQLite main 10 / audit 2 模式、完整性、外键、已 checkpoint 的 WAL、导出前后文件摘要及完整列集合。
- 30 张源表全部存在，按依赖顺序导入；所有 30 表及 bff.records 检查为空。仅允许并替换初始化时两条精确系统默认记录，修复 member_sync_meta/settings 主键冲突。
- 整数使用 BigInt / 安全整数的同一摘要表示；TEXT 逐字节保留，BLOB 按二进制比较。历史日期、JSON 仍是 TEXT，不擅自重写历史内容。NUL 和超出应用安全整数范围拒绝导入。
- 新目标库由显式 DDL 初始化，导入由单事务保护；不 TRUNCATE、不跳过脏数据、不递归重新获取或双重释放连接。成员同步触发器造成的计数变化在事务内恢复到源值。
- 所有 identity 通过 setval 校准，核验读取实际 sequence 状态且不消耗 nextval；全表行数/摘要一致、外键约束已验证。CLI 额外扫描权威业务字段的本地资源引用，核对实际恢复文件。
- URL 仅由私有 POSTGRES_MIGRATION_URL 提供；--target-database 必须与 URL 精确一致，目标名限隔离命名。报告 run-id 禁止目录穿越，报告不含连接口令和数据行。

## 验证

`pnpm test:release` 使用真实迁移创建的完整 SQLite 源（30 表均非空），实际导入全新 PostgreSQL、比对摘要与资源，再验证新业务写入 ID。注入 beforeCommit 异常后检查用户表为空，并重新启动 SQLite 恢复副本。

`pnpm test:migration` 仅承担 URL/参数、整数/TEXT/BLOB 摘要和文件校验边界单测；不冒充真实导入演练。
