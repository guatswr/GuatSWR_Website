# PG-05 原生备份与恢复修复证据

日期：2026-11-08。状态：CODE_VERIFIED（本地隔离验证；生产未验收）。旧版只转储部分表的 JSON 格式及只记录文件名的资源“备份”已移除，不支持当作恢复点。

## 实现

- 版本 2 包含 pg_dump custom-format 原生转储，覆盖 main / audit / bff 全部 32 表（30 张迁移数据表、schema ledger、BFF records），包含 BYTEA、约束、触发器和序列。
- 数据库采用导出的一致性快照；创建私有 asset-cleanup fence 并排空 cleanup advisory lock 后复制资源。复制 public、asset-quarantine、asset-publications 的真实文件字节，逐文件大小和 SHA-256 校验；拒绝符号链接、路径穿越、复制期间文件变化和缺失的权威本地资源引用。依赖现有不可变发布协议，fence 保留期间不做物理删除。
- 收据记录模式版本、应用 sourceRevision、数据库转储摘要、逐表摘要和资源清单。应用 revision 为 uncommitted-review 时只供本地 review，正式发布必须固定已审核源码与镜像。
- 恢复先核验包、文件字节和目标名称，再要求全新空数据库及不存在的资源目标。pg_restore --single-transaction --exit-on-error 执行后检查结构指纹、所有表摘要、资源引用和实际序列状态；恢复最小权限。整个数据库/文件恢复不是跨资源原子事务，失败候选不得放行，使用另一个空目标重试。
- 恢复资源位于 target/data/public、target/data/asset-quarantine、target/data/asset-publications；不把隔离区和发布日志丢在运行时不会读取的目录。
- backend Docker 镜像打包固定 PostgreSQL 18.6 pg_dump/pg_restore 与独立动态加载器/依赖；不在 Node 进程中替换其 OpenSSL。凭据通过私有环境变量传递，不放在命令参数中。
- ops_backup.py 按实际 DATABASE_DRIVER 调用 native bundle 或旧 SQLite 流程，使用可执行的 Node 调度探针。统一 GPG、远端 checksum/原子接收与收据流程仍保留。PG 本地保留点尚未设置自动删除，需按恢复验收与磁盘预算配置。

## 验证

`pnpm test:release` 实际 pg_dump / pg_restore 到新数据库，逐字节解密恢复的 BFF 会话，核对 PNG、隔离区和日志文件，恢复后第一笔自增 INSERT 成功。篡改资源时必须拒绝。演练还从恢复候选启动应用并读取切换后新增文章和图片。

`python -m unittest scripts/test_ops.py` 实际执行 SQLite Node 探针并检查双驱动编排；release 测试另用真实 PG 最小权限连接执行同一探针。

## 上线边界

这是定时逻辑备份，RPO 受备份间隔限制，不提供 PITR。生产异地密钥解密、定时器触发、告警投递、磁盘峰值和真实规模恢复仍需在目标环境验收。崩溃遗留 fence 时，先确认没有备份和 cleanup 任务，再人工处理；禁止无条件删除 fence。
