**结论：Hermes 的设计系统与性能工作已复验；补齐弹窗异常处理和验收工具后，当前共享布局通过本地验收。公开业务页、表单和后台仍待迁移，当前不具备上线条件。**

## 证据

- 独立复验未修改的 Hermes `eca246c`：四项递归检查通过，单测 15/15、E2E 18/18；样例/布局 LCP 中位数 1555/1505ms。该提交远端 Windows CI 失败于 Lighthouse `NO_NAVSTART`，Linux 构建通过，不能称远端全绿。
- 后续加固曾由 Codex 引入静态 Reka Primitive，增加首屏依赖并产生一次有效的 1804.8ms 超预算结果；该失败已保留。最终改用原生 SSR 按钮，Reka 弹窗按需加载，支持首次激活、失败提示、重开及焦点返回，清除原有无条件预取和定时器。
- 最终 Windows：typecheck/lint/test/build 全通过；单测 15/15、E2E 20/20；桌面/手机、日/夜间的 10 组旧站布局对照零差异。全部客户端 JS 125,861B gzip，生产 sourcemap 为 0。
- 最终移动 Lighthouse 三次有效样本的中位数：样例 **100 分 / 1509ms**，布局 **99 分 / 1656ms**。门槛仍为 ≥95 / ≤1800ms；没有丢弃慢样本，没有重跑有效结果。服务器预热、浏览器冷缓存；不代表完整真实页面或旧站速度对照。
- Codex 独立 Linux 容器构建：四项递归检查通过，单测 15/15、0 sourcemap、JS 125,859B gzip；隔离运行时通过 SSR、配置投影、凭据隔离、压缩及 CSP 一致性检查，容器已移除。机器证据见 [design-validation.json](evidence/design-validation.json)。
