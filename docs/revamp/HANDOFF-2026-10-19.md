## 1. How to reproduce the numbers

```sh
cd /e/Taropoi/workspace/GuatSWR_Website
. .tools/env.sh          # Node 24.15.0, pnpm 11.25.0, TEMP/TMP, browser cache
pnpm -r typecheck && pnpm -r lint && pnpm -r test && pnpm -r build
node scripts/revamp/check-artifacts.mjs
node --test web/scripts/e2e-isolated.test.mjs
```

The machine runtime is Node 22.23.2 and **must not** be used: nuxt-security 2.6.0
needs 24.15.0. Never run `pnpm install` casually — the lockfile is the
dependency set.

The E2E suite needs a built `.output` and a free port base:

```sh
E2E_PORT_BASE=4100 node web/scripts/e2e-isolated.mjs --max-per-batch 2
```

The runner starts a fresh fixture + Nuxt server for every two tests, because the
whole suite in one server saturates nuxt-security's rate limiter and produces
false "element not found" failures. Bare `playwright test` is **not** a valid
signal here. Builds and Playwright runs are serialized through
`.tools/build.lock` (`mkdir` to take, `rmdir` to release) since `.nuxt/`,
`.output/` and `test-results/` are shared.

## 4. Defects the migration found and fixed

These were all found by executing code that had never run, and each is covered
by a test or a verified measurement:

- `bff-auth-service.login()` returned an undeclared `expiresAt` — a
  `ReferenceError` on **every** login.
- `guest-upload.detach()` removed its listeners before destroying the stream, so
  an aborted upload leaked its concurrency slot and temp directory.
- `guest-drafts.issue()` never checked its record TTL, so an expired cookie was
  reused instead of rotated.
- `EventForm` read its model through `computed(() => form.state.values)`; in
  `@tanstack/vue-form` 1.33.5 `form.state` is a plain snapshot, so the model
  never updated and every submit was rejected client-side.
- `EventCard` rendered `toLocaleString()` verbatim — `zh-CN` on the server,
  `en-US` in the browser, so every card with a schedule failed hydration.
- The admin star export collided with `public.js` on three row schemas, which an
  ambiguous star export would have dropped at runtime.
- An `<img>` whose `src` was rejected was still emitted without attributes;
  `?page=02` returned 400; `safeLocalReturnPath` accepted `/admin\t`.
- Tailwind 3 → 4: a variant `text-*` utility carried its own `line-height` in
  TW3 and won the cascade, while TW4 routes it through `--tw-leading`, so a
  `leading-*` on the same element won above the breakpoint. Found independently
  on the homepage, the event board and the activity page.
- Tailwind 4's `space-y-*` emits `margin-block-end` on an inline preceding
  sibling, where TW3 put `margin-top` on the control.
- `web/app/assets/css/main.css` was missing five archived dark overrides
  (`bg-gray-800` and four `border-gray-*` rules carrying `!important`), which
  beat any `dark:border-*` utility.

## 5. Blockers — read these before accepting anything

**5.1 `#entry` on a warm reload (critical, real users).** Reloading any page in
the same browsing context renders Nuxt's 500 page with
`Failed to resolve module specifier "#entry"`; `onMounted` never runs. It is a
race between the document parse and the modulepreload fetches: on a cold cache
the preloaded chunks arrive after the inline import map is registered, on a warm
cache they resolve first. Reproduced on `/`, `/members` and `/login`, in
headless-shell and full Chromium, and disabling the HTTP cache hides it. It is
**not** login-specific and it destabilises several E2E cases across specs. The
SSR head emits 26 `<link rel="modulepreload">` hints before the import map.
Diagnosis and probes: [logs/07-login-e2e](logs/07-login-e2e/README.md) §3.2.

**5.2 The route-level JavaScript budget is exceeded.** Measured in a real
browser on a cold cache: **177,477 B gzip against a 153,600 B ceiling**. This is
client code, not the BFF — the server layer ships no browser bytes. The
conservative all-JS sum is 269,445 B. Checklist 82.

**5.3 `/logs` light-mode parity needs a product decision.** The remaining
differences are raw versus redacted `details`; passing them would mean
publishing the client IPs and config keys the projection exists to drop.

**5.4 `/members` parity** is `ProgressiveImage`'s `managed = !painted` against
the archived IntersectionObserver placeholder — four comparisons.

**5.5 Capture-protocol cases.** The archived `RouteProgressBar` (never ported)
and the fixed navbar land inside several tall mobile crops. Five comparisons;
these are protocol questions rather than page defects, and any change must keep
the zero-pixel rule and the whole-device-pixel crop honest.

**5.6 One approved deviation.** The archived dark signup modal never receives
its dark theme — its scoped selectors cannot match a dialog Element Plus
teleports to `<body>` — leaving an invisible heading and buttons. The project
owner approved keeping the readable port on 2026-10-19; `events-visual.spec.ts`
asserts the intended difference and a 4.5:1 contrast floor instead of zero
pixels. Full reasoning in `logs/06-events-e2e/` and the commit message.
