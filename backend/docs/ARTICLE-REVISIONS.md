# 文章修订记录

主库显式升级至 **main7** 后启用。旧主库仍可按兼容规则启动并编辑文章；新增历史接口在未升级时返回 503。启动不会执行 DDL。此次不修改原 71 项接口的输入、响应或发布逻辑。

## 记录范围

- 新文章发布、草稿创建、已有文章保存会记录标题、标签、日期、摘要、正文、封面、相册和当时的发布状态。
- 记录修改人 ID、姓名快照、毫秒时间、文章内递增版本号和操作类型。管理员删除或改名后，历史中的姓名仍可辨认。
- 相同内容且状态相同的重复保存不新增版本；事务失败不会留下成功修订，网络中断时应先刷新核实结果。文章更新、修订插入在同一个 SQLite 写事务内完成，并继续使用现有图片发布事务。
- 旧文章在迁移时创建 `baseline` 快照，内容保持原样，时间表示“采集基线的时间”，不代表过去的真实编辑时间。启用前的编辑过程无法重建。
- 中断创建留下的临时、未完成草稿不被当作已经保存的文章版本；成功发布的快照使用最终图片地址。

## API

以下路径相对于 `/api/activities`，均返回 `Cache-Control: private, no-store`。其中 `/:id/revision-log` 为公开已发布文章的修订摘要接口；其余三项均需要有效管理员 JWT。普通管理员可管理正常文章的修订；已软删除文章的历史仅站长可查看，恢复内容前必须先恢复文章本身。

| 方法与路径 | 说明 |
| --- | --- |
| GET `/:id/revision-log?page=1&limit=20` | 公开已发布文章的发布记录摘要（隐藏草稿、内部版本 ID 与历史全文） |
| GET `/:id/revisions?page=1&limit=20` | 管理员版本摘要列表，最新在前；每页最多 100，页码最多 1000000 |
| GET `/:id/revisions/:revisionId` | 指定文章的完整快照，版本必须属于该文章 |
| POST `/:id/revisions/:revisionId/restore` | 恢复内容为新修订；请求体 `{ "base_revision": 123 }` |

公开日志返回 `available/page/limit/total/items`，条目仅含公开连续序号 `sequence`、`action`、`actor_name`、`created_at` 与 `changed_fields`；草稿或软删除文章返回 404，主库未升级 main7 时返回 `available: false`。管理员列表返回 `page/limit/total/current_revision/items`；摘要包含 `id/activity_id/version/action/actor_name/created_at/restored_from/title/source_status/changed_fields`，不包含正文。详情补充标签、日期、摘要、正文、封面和相册。`images` 在 HTTP 响应中为数组。

`base_revision` 是页面读取到的当前修订 ID。恢复事务重新检查当前身份和版本；若已有新保存，返回 409，不覆盖新内容。恢复成功返回 `{ "revision_id": 124, "restored": true }`，同时写入 `RESTORE_ACTIVITY_REVISION` 审计意图。内容已一致时返回当前 ID 和 `restored:false`，不制造重复版本。

恢复仅替换内容，不修改当前发布状态、删除状态、创建时间或原创建人；更新人变为当前操作者。旧修订保留，恢复结果本身是新修订。没有删除/修改单条历史的 API。

## 图片与删除

资源引用扫描、回收检查同时考虑历史快照中的封面、相册和正文/摘要插图，仍在历史中引用的图片不会按孤立资源处理。功能只能保留现存图片，不能重建启用前已经遗失的文件。保存完整快照会增加数据库和备份体积，当前不自动裁剪历史。

软删除保留历史；站长永久清空文章时，通过外键级联删除对应修订，原资源清理流程继续重新检查剩余引用。共享图片仍受其他文章或记录保护。

## 前端

后台文章列表和编辑器均有「修订记录」入口，使用居中、可滚动的原生弹窗展示版本及与当前保存内容的对照。正文按源文本展示，不执行历史 HTML/脚本。图片仅展示现有站内上传资源。

编辑器存在未保存修改时，可以查看但不能恢复。恢复需要二次确认；冲突会刷新当前内容，要求重新核对，不自动重试覆盖。恢复后关闭旧编辑状态并刷新列表与公开文章缓存。公开活动正文页 `/activity/:id` 的「查看更改记录」通过 `/api/content/activity/:id/revisions` 展示已发布修订摘要（操作类型、记录者、时间与变更字段范围），不加载历史全文或草稿快照，并提供跳转 `/admin/activities?history=:id` 供管理员查看完整历史与恢复。

Nuxt BFF 使用独立的固定路径 `/api/bff/admin/article-revisions`，仅转发白名单操作；恢复还需要 Origin、CSRF、受限请求体和正整数 ID 校验。

## 本地升级

先备份现有双库及资源，再运行：

```text
pnpm --filter guiair-backend db:migrate upgrade --data-dir /absolute/private/data
```

main7 新增表和初始快照，旧迁移 SQL/checksum 不变。已升级的数据库不能直接交给不认识 main7 账本的旧构建；回退应使用保留兼容校验的代码，不能用旧数据库快照覆盖新写入。

## 验证

前端 760、共享包 79、原生生命周期 17 项通过；后端全量 2049 项通过，1 项既有跨平台场景跳过。专项覆盖记录去重、最终图片路径、并发保存、事务回滚、删除与权限、草稿状态保留、main6→7 基线迁移、旧账本保持和历史图片引用保留。

实际生产构建 BFF 与 Chromium UI 各 2 项通过，包含原 Bot 流程回归；新增流程覆盖公开文章热缓存失效、CSRF、非法 ID、恢复冲突与再次确认、取消恢复、未保存编辑保护、手机弹窗和公开页结果。本地原库仅以只读方式预览基线，未替换原文章内容。

构建验证时发现 Windows 嵌套依赖链接漏拷贝导致独立服务缺少 `entities` 的 ESM 文件，已在 Nitro 配置中将 `rehype-raw → hast-util-raw → parse5 → entities` 解析链一并打包；最终独立服务启动及公开 Markdown 渲染验证通过。此前失败记录保留于本地验证产物。
